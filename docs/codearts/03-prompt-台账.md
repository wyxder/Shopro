## 一、Prompt 设计基线（本项目统一模板）

### 1.1 结构化五段式

```text
[角色] 你是 <项目角色>，熟悉 <技术栈/业务域>。
[上下文] 相关文件：<路径>；约束：<规范文件/接口契约>。
[目标] 完成 <单一可验收目标>。
[边界] 禁止 <越权改动/新增依赖/改历史迁移>；必须 <复用现有工具/保持契约>。
[验收] 输出 <文件/命令/测试>；通过标准：<构建/测试/人工检查点>。
```

### 1.2 本项目附加约束（来自 `AGENTS.md` 与 `docs/技术开发规范.md`）

| 约束 | 内容 |
|---|---|
| 提交信息 | 中文、说明模块与原因、禁止使用"完善" |
| 目录职责 | 页面/组件/API/Hook/lib 各归其位，禁止页面直连 Supabase |
| 契约优先 | 先定 `ApiResponse<T>` / 权限码 / 状态枚举，再写实现 |
| 资金路径 | 扣费、退款、回调必须事务化、可审计、有日志 |
| 安全 | 禁止硬编码密钥；密钥只从环境变量/Secrets 读取 |
| 验收 | 必须给出可执行命令与结果，不以"看起来正确"结案 |

### 1.3 Prompt 反例与纠偏

| 反例 | 问题 | 纠偏写法 |
|---|---|---|
| "帮我优化一下这个页面" | 无目标、无边界、无法验收 | "将 `VideoEditPage` 播放主时钟改为 rAF，保持 60FPS 游标，不改动轨道数据结构；验收：连续播放 30s 无 seek 抖动" |
| "把积分功能做好" | 范围过大、易越权 | "仅实现 `deductUserCredits` 的余额校验与 `credit_logs` 写入，不改 UI；验收：余额不足不扣费、成功写流水" |
| "顺便把 README 也改了" | 混合任务，难以归因 | 拆成独立任务，单独验收、单独提交 |

| 指标 | 定义 | 采集方式 | 当前值 |
|---|---|---|---|
| 一次通过率 | 首次产出即通过验收的任务占比 | 台账"状态"列统计 | 待统计 |

| 人工修改行数占比 | 人工 diff 行数 / 总变更行数 | `git diff --numstat` | 待统计 |

> 建议在赛前用最近 10 个任务补一次统计，填入上表；这比空泛描述"效率很高"更有说服力。

## 四、登记规范

1. 每次码道任务结束立即登记，不事后批量补写。
2. Prompt 可脱敏（隐藏密钥、内网地址），但不得改写意图。
3. 产出必须落到具体文件或提交，禁止只写"生成了代码"。
4. 被否决的方案也要登记，并写明否决原因——这能体现真实迭代。
5. 截图存入 `screenshots/`，文件名与台账编号一致（如 `P-002-01.png`）。
