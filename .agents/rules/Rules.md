# Rules.md · Shopro AI 开发红线与执行规则

> 本文件是**强制约束**，与 [docs/技术开发规范.md](docs/技术开发规范.md)（细则）、[AGENTS.md](AGENTS.md)（协作与提交）配套使用。
> 冲突时优先级：**本文件 > 技术开发规范 > 个人习惯**。确需例外，必须在 PR 中写明原因、影响与回滚方案，并取得负责人确认。

---

## 一、通用红线（任何代码都适用）

1. **禁止**在代码、注释、日志、文档、截图中出现真实密钥、Token、支付私钥、用户隐私。
2. **禁止**新增未经评审的第三方依赖、第二套 UI/状态/请求库。
3. **禁止**绕过 `pnpm lint`（类型检查 + biome + ast-grep + Tailwind 构建 + 构建测试），不得通过注释规则、改配置排除目录来“变绿”。
4. **禁止**提交调试代码（`console.log` 残留、mock 数据、临时开关、写死的测试账号）。
5. **禁止**在 `master` 直接提交业务改动；分支命名 `feature/…`、`fix/…`。
6. 提交信息必须是**中文**、说明模块与目的；**严禁使用“完善”，统一用“新增”表述**。

## 二、前端规则

| 编号 | 规则 |
|---|---|
| FE-1 | 所有数据请求必须经 `src/api/*.ts` + `handleApiRequest`，返回 `ApiResponse<T>`；页面禁止直接 `createClient` 或手拼 URL |
| FE-2 | 新代码必须通过 `tsgo -p tsconfig.check.json`（`strictNullChecks`）；`any` 仅限第三方边界且 3 行内收窄 |
| FE-3 | `<Button>` 必须可交互：`onClick` / `type="submit|reset"` / `asChild`，或位于 `*Trigger`、`<Link>` 内 |
| FE-4 | Button 对比度：`outline` 禁止配 `text-foreground`、`text-white`、`text-gray-*`；默认 variant 禁止 `text-primary` |
| FE-5 | `SelectItem` 禁止空字符串 `value`；全选使用具名值（如 `all`） |
| FE-6 | Toast 统一 `import { toast } from "sonner"`，禁止 `@/hooks/use-toast` |
| FE-7 | Radix `*Trigger asChild` 内禁止包 `FormControl`（会导致点击失效） |
| FE-8 | Google 登录统一 `signInWithSSO`，禁止 `signInWithOAuth({ provider: 'google' })` |
| FE-9 | 流式文本统一走 `src/lib/sse.ts`；长任务轮询必须带退避、最大次数与超时 |
| FE-10 | 组件卸载必须取消在途请求与订阅，禁止卸载后 `setState` |
| FE-11 | 拖拽/时间轴交互：拖拽过程不写全局 state，松手才提交；动画只动 `transform`/`opacity` |
| FE-12 | 颜色、圆角、阴影必须使用主题变量；必须适配 375 / 768 / 1440 与暗色主题 |
| FE-13 | 错误文案中文、面向用户，不暴露堆栈、表名、上游报文 |

## 三、后端规则

| 编号 | 规则 |
|---|---|
| BE-1 | Edge Function 必须按固定顺序实现：CORS 预检 → 方法校验(405) → JWT 鉴权(401) → JSON 解析(400) → action 白名单(400) → 密钥缺失(**503**) → 业务 |
| BE-2 | `GET` 请求**禁止**带 body，参数必须拼在 URL 上 |
| BE-3 | 公共逻辑必须放 `supabase/functions/_shared/`，禁止跨函数复制；CORS 白名单只允许 `_shared/cors.ts` 登记域名 |
| BE-4 | 用户身份**只能**取 JWT 的 `auth.uid()`，禁止信任请求体 `user_id`；`service_role` 仅服务端内部使用 |
| BE-5 | 新表必须启用 RLS，默认拒绝，再按最小权限授权；跨租户查询必须显式带租户条件 |
| BE-6 | 余额/积分变更**只能**走 `SECURITY DEFINER` RPC（行锁 + 校验 + 流水同事务）；禁止前端或其他途径直接改余额 |
| BE-7 | 冲正/退款只写反向流水（`REVERSAL`），禁止改余额或删流水；退款 RPC 仅 `service_role` 可调 |
| BE-8 | 扣减、发放、订单状态、支付回调必须具备幂等键 + 单向状态机；重试不得重复扣费 |
| BE-9 | 支付回调必须验签、校验金额与订单号；订单快照（套餐/价格）必须落库 |
| BE-10 | 数据库迁移只增不改，格式 `000NN_描述.sql`，必须可在空库顺序执行 |
| BE-11 | 日志必须带 `traceId`；禁止打印完整 Prompt、Token、手机号、身份证、签名 |
| BE-12 | 上游调用必须有超时、重试上限、降级与熔断；错误对外归一化，禁止透传上游原始错误体 |
| BE-13 | Python 网关必须校验调用方凭据，未配置凭据时**拒绝服务**，禁止成为公网裸代理 |
| BE-14 | 运营后台接口必须 RBAC 校验并写审计日志；分页与字段白名单不可省略 |

## 四、Agent / AI 服务规则

| 编号 | 规则 |
|---|---|
| AI-1 | 分层不可穿透：接入层 → 编排层 → 能力层 → 资产层；业务代码禁止直接调厂商 SDK 或写死模型名 |
| AI-2 | 模型必须经 `Provider` 抽象接入，支持配置化切换与降级；版本、`request_id`、成本必须入库 |
| AI-3 | Prompt 必须版本化（ID + 版本 + 场景标签），线上只引用版本；禁止直接改线上常量 |
| AI-4 | 结构化输出必须 JSON Schema 约束 + 解析失败重试 + 模板降级 |
| AI-5 | 用户输入只进入数据槽位，**禁止**拼接进系统指令；检索内容必须标注来源边界 |
| AI-6 | 长任务统一 `submit → request_id → query`；状态持久化，禁止放内存；每次尝试写 Attempt |
| AI-7 | 最终失败必须自动冲正积分；同一 `request_id` 重复查询不得重复扣费 |
| AI-8 | 情感标注必须是结构化数据（`emotion + intensity + 起止时间`），下游映射确定性可复现；语音与字幕同源 |
| AI-9 | 生成内容必须过敏感词/违规检查；数字人形象与声音必须有授权记录 |
| AI-10 | 改动 Prompt/模型/版本必须跑离线评测集（≥30 条真实样例），关键指标劣化 >10% 必须回滚 |
| AI-11 | RAG 检索必须带业务过滤（租户/品类/语种），Top-K 默认 5，禁止无过滤全库召回 |

## 五、测试与发布规则

1. 提交前 `pnpm lint` 五项全绿；核心路径（登录、扣费、生成、冲正、支付回调）必须有冒烟验证。
2. 涉及数据库迁移、支付、权限、模型切换的改动必须双人评审。
3. 上线顺序：迁移（测试库预演）→ Edge 灰度 → 前端 → 主链路核对 → 观察告警。
4. 任何上线必须可回滚；迁移只增不删，保证旧版本兼容。
5. 每日对账：积分发放、消耗、冲正与订单金额必须一致。

## 六、AI 编码助手（Agent）执行规则

1. 修改前先读相关文件与既有约定，不臆造 API、字段、错误码。
2. **AI 写边缘，人守核心**：UI、样板、文档可加速；事务、权限、支付、状态机、扣费必须人工逐行确认。
3. 不得为了“跑通”而注释规则、放宽类型、添加 `any`、关闭 RLS 或跳过鉴权。
4. 不得自动创建无关文档、临时脚本、调试文件；交付物放 `docs/`，临时产物放 `scratch/` 并清理。
5. 每次文件变更结束时按 [AGENTS.md](AGENTS.md) 的 Git 流程执行：`git add .` → 中文提交（禁用“完善”）→ `git push`；无法推送时立即汇报状态。
6. 报错时先定位根因，不得反复重试同一命令；无法收敛时向用户说明阻塞点与备选方案。

## 七、例外与豁免

- 例外申请必须包含：**为什么必须破例、影响范围、补偿措施、回滚方式、期限**。
- 安全类红线（密钥、鉴权、RLS、余额 RPC、支付验签）**不设例外**。
- 临时豁免必须在 7 天内消除，或转为正式方案写入规范。
