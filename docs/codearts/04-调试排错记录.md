## D-01 生成视频成功但积分未扣除

| 项 | 内容 |
|---|---|
| 现象 | 视频生成成功，顶栏余额与 `credit_logs` 均无变化 |
| 影响 | 核心计费链路失效，属于资金类 P0 |
| 排查路径 | ① 对比"生成按钮"与"充值/兑换"两条链路的余额变更；② 检查是否有页面绕过统一 Hook 直接调用生成；③ 查 `credit_logs` 是否缺少 `video_generate` 记录 |
| 根因 | 生成动作未统一接入 `deductUserCredits`，扣费与业务提交脱节 |
| 修复 | 生成前统一走 `useCredits.deductUserCredits`，成功写 `credit_logs`，失败回滚；全站广播 `credits_changed` |
| 回归 | 余额 ≥10 生成一次，余额 -10 且流水新增；余额 <10 被 `creditGuard` 拦截且不产生流水 |
| 证据 | 提交 `72afae1`；`docs/doc/TEST_CASES.md` TC-B2 / TC-B3 |

## D-02 商品卡"创建视频"点击无响应 / 跳转后商品未选中

| 项 | 内容 |
|---|---|
| 现象 | 阶段一：点击按钮无任何反应；阶段二：能跳转但工作台未选中商品、脚本未装载 |
| 影响 | 商品到视频的主转化路径中断 |
| 排查路径 | ① 检查卡片 `onClick` 是否绑定 `onCreateVideo`；② 检查路由跳转是否携带 `state`；③ 检查目标页是否消费 `location.state` 并触发选品 |
| 根因 | 卡片漏绑事件；路由跳转未保留 `location.state` |
| 修复 | 补事件绑定；新增 `RedirectWithState` 透传机制，目标页读取 state 后自动装载商品与脚本 |
| 回归 | 商品列表点击"创建视频" → 跳转 `/video/create` → 商品已选中、脚本已填充；刷新后状态不误留 |
| 证据 | 提交 `7021479`、`341c6f6` |

## D-03 视频编辑器播放卡顿、播放头抖动

| 项 | 内容 |
|---|---|
| 现象 | 多轨工程播放时游标抖动，频繁 seek，长时间播放后明显掉帧 |
| 影响 | 核心创作体验，直接影响"操作流畅"评分 |
| 排查路径 | ① 观察播放头驱动源；② 统计单位时间 seek 次数；③ 对比 `requestAnimationFrame` 与 `setInterval` 的时间精度 |
| 根因 | 使用挂钟定时器驱动播放头，与 video 原生时钟不同步，误差累积后触发纠错 seek |
| 修复 | 主时钟改为 rAF + video 原生时钟；游标 60FPS 渲染；素材 Blob 预载减少卡顿 |
| 回归 | 连续播放 30s，游标与画面同步，无高频纠错 seek |
| 证据 | `docs/doc/TEST_CASES.md` TC-D6；相关性能提交 `bbb22f4` |

## D-04 视频网关参数规格差异导致 400 静默降级

| 项 | 内容 |
|---|---|
| 现象 | 部分视频模型（Wan3 / HappyHorse 等）提交失败，前端无明确报错，表现为"生成没反应" |
| 影响 | 多模型矩阵可用性下降，用户误判为平台故障 |
| 排查路径 | ① 用 `scratch/test_wan3.js`、`test_happyhorse.js` 直连网关复现；② 对比各模型 `duration / ratio / resolution` 参数边界；③ 查看代理层是否吞掉 400 |
| 根因 | 各模型参数规格不同，统一入参导致 400；前端未区分"可重试/不可重试"错误 |
| 修复 | 按模型规格适配参数；代理层透传错误码与信息；前端显式提示并禁止提交侧自动重试（防重复扣费） |
| 回归 | 各模型按规格提交成功；超时注入时不自动重试，返回可恢复错误 |
| 证据 | `scratch/test_wan3.js`、`test_wan3_proxy.js`、`test_happyhorse.js`、`test_happyhorse_proxy.js`；TC-C4 / TC-C5 |

## D-05 支付宝主通道异常时无支付兜底

| 项 | 内容 |
|---|---|
| 现象 | 支付宝下单接口异常时，收银台停留在加载态，用户无法完成充值 |
| 影响 | 直接阻断付费转化 |
| 排查路径 | ① 模拟下单接口 4xx/5xx；② 检查收银台异常分支；③ 检查是否有手动扫码备用路径 |
| 根因 | 支付路径单一，异常分支未提供降级入口 |
| 修复 | 主通道失败时静默切换手动扫码支付；保留订单状态查询与回调入账 |
| 回归 | 拦截下单请求后，收银台仍展示可扫码的备用支付方式；到账后积分正常入账 |
| 证据 | 提交 `777acc8`；`docs/doc/TEST_CASES.md` TC-B5 |

## 排错方法沉淀（可复用到后续任务）

1. **先复现再改**：用 `scratch/` 最小脚本直连第三方，隔离前端/代理/上游三层。
2. **资金路径双查**：业务状态与 `credit_logs` 必须同时核对，不能只看 UI。
3. **错误分级**：可重试（网络抖动）与不可重试（参数错误/已扣费）必须区分，提交侧禁止盲目重试。
4. **回归留痕**：每个修复在 `TEST_CASES.md` 增补编号与结果，避免"修了但没证据"。
5. **口径同步**：修复涉及数量/接口时，同步 README 与 `CURRENT_STATE.md`，由契约脚本兜底检查。
